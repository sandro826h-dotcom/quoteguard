## 图注

**图 1**　报价原件经视觉转写（仅图片）后由大模型逐份抽取 18 个条款，每个条款附原文片段；另一家模型对同一报价独立抽取。程序核对片段是否为原文子串，比对两次抽取得出冲突，检查必需条款得出缺口。确定性核价、包税合理性与资质证据判定都由程序完成，所用税率、汇率、承运商规则和登记库均为带日期的快照。决策在可行集内取确定成本最低者；缺失或冲突条款在取值集合内变化会改变最优解时，输出追问清单。灰底为大模型调用，白底为确定性程序，虚线框为快照与运行记录。

**图 2**　M0 为卖家把报价贴给通用大模型直接询问；M1 把检查清单、计算规则、参数快照和登记库表写进提示词，仍由模型单次给出结论；M2 起改为大模型逐份抽取、程序核价，M3 加包税合理性与资质证据门控，M4 加出处核对、冲突与缺口识别、跨模型复核和按取值网格判定的追问。实心点表示方法包含该组件，空心点表示只在提示词中要求模型自行完成。M0 只在输出格式中给出“需要追问”这一选项，不提供取值集合，图中不标追问。6 个模型配置各跑 M0–M4。

**图 3**　真实报价集来自 10 份公开原件（7 个发布主体），拆为 28 个报价单元（货代 22，承运商公布价 6）。反事实任务集的费用结构取自真实单元与承运商官方规则；生成器在锁定商业事实的前提下变换呈现方式，标准答案由 Python 与 Excel 两套独立计算器交叉核对（差额不超过 0.01 元），追问类答案在取值网格上逐值验证。开发集 24 个只用于调试提示词；测试集 48 个用测试池模板，在 M0–M4 提示词与冻结协议定稿后以种子 20261011 生成，记录哈希，生成后不查看金标签调整任何方法。灰底为人工步骤。

**图 4**　盲标子集 15 个单元按固定种子分层抽取，两份初标在仓库外独立完成，由整理原件的队友对照原件逐字段审定全部 270 个字段，按规范第七节裁决；盲标子集的两份初标由大模型生成，金标签以人工全量审定为准，这一偏离记于项目日志（2026-10-12）。其余 13 个单元由 Claude（不属于 6 个实验配置）初标，标注人 A 逐字段复核。全部标签记录哈希之后才运行 6 个配置的真实集抽取。
