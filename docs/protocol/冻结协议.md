# QuoteGuard 正式实验冻结协议

本协议规定正式实验的数据、配置、方法、终点、统计、执行与停止规则。冻结后按本协议执行；任何偏离写入 `docs/protocol/偏离记录.md`，注明日期、原因与影响，不改本文件。冻结时本文件的 sha256 记入 `docs/protocol/冻结记录.md` 与 PROJECT_LOG。

## 一、依据文件

下列文件在冻结时的 sha256 列于第十节，执行以这些版本为准：

- `docs/plan/AIC_最终方案.md`：方法阶梯、实验、主终点与事前决策规则（第六、七节）。
- `docs/plan/任务生成规格.md`：任务层级、约束、标准答案与冻结方式。
- `docs/plan/方法实现规格.md`：M0–M4 的流水线、复核、输出上限、评分。
- `docs/plan/真实报价集_口径与标注规范.md`：真实报价集的计数、纳入、标注、评分与参照下限。
- 代码：冻结提交（第十节）中的 `src/quoteguard/`、`configs/models.yaml`、`data/taskgen/`（v4）、`data/params/tariff_snapshot_2026-10-09.json`。提示词以 `src/quoteguard/prompts.py` 为准。

## 二、测试集

- 生成：`taskgen` 以 `--split test`、每层 12 个任务（显式、隐含、冲突、信息不足四层，共 48 个）、`--verify-xlsx` 生成，seed = 20261011，输入配置为 `data/taskgen/`（参照下限 v4），参数快照 tariff-2026-10-09。
- 测试集在本协议冻结之后生成。生成后的 `data/tasks/test/manifest.json` 哈希与生成所用提交号记入 `冻结记录.md`；生成失败按任务生成规格第四节处理（不换 seed，修正生成器后整体重新生成），并写入偏离记录。
- 开发集（`data/tasks/dev`，按 `data/taskgen/dev_v3` 生成）只用于调试，不进入任何正式结果。
- 测试集生成后不查看金标签调整任何方法、提示词、词表或阈值。

## 四、方法

- M0、M1、M2、M3、M4 按方法实现规格第五节。M4 对全部候选合并复核方已有的抽取，不另发请求。
- M4_trig（只复核满足风险触发条件的候选）由同一批观测离线生成，只用于 E3，不进入主终点。
- M2–M4 的归一化词表只来自开发池模板与事先写定的通用词表；测试池措辞上的词表覆盖率单独报告。

## 五、终点与统计

主终点三项为一个 Holm 族，族内总体 α = 0.05（方案第七节）：

1. E1 决策正确率（含正确追问）：M4 对 M0，非显式三层 36 个任务，6 个配置分层，双侧优效。
2. E2 风险项检出 micro-F1：M4 对 M0，全部 48 个任务，6 个配置分层，任务为单位交换方法标签的置换检验，双侧。
3. 成本主张：低成本档 M4 对同厂商强模型档 M0 的决策正确率（ds_flash 对 ds_pro，qwen_plus 对 qwen_max，2 层分层），非显式 36 个任务，非劣效界值 −5 个百分点，单侧。

- 二分类指标用 McNemar 精确检验，跨配置合并用分层置换检验；连续指标用配对置换检验；置信区间按任务整簇 bootstrap。重抽与置换次数 B = 9999（`score --B 9999`），随机种子 20261011。
- 其余比较为次要结果，只作描述，给 95% 置信区间。
- 调用最终失败（第七节）的配置、方法、任务记为解析失败：决策记为错误，风险项记为未检出，不从分母中剔除；失败数按配置与方法报告。

## 六、事前决策规则

按方案第七节“事前决策规则”表执行，结果出来后不改主线。

## 七、执行

- 顺序：先运行全部转写，再运行 M0、M1、抽取；同一服务商内按任务编号顺序；不同服务商可并行。
- 调用失败：执行器按现行设置重试；最终失败的调用在同一批次结束后以流式补跑一次，补跑仍失败记为最终失败。补跑另立批次目录，不改原批次记录。
- 千问免费额度用完（HTTP 403，`AllocationQuota.FreeTierOnly`）：停止该批次，保存已完成记录，报告需要更换百炼 key；不重试、不换模型，换 key 后从断点续跑。
- 硅基流动余额不足：同上处理，报告需要充值。
- 批次按服务商划分：DeepSeek 官方（ds_pro、ds_flash、ds_flash_think）、阿里云百炼（qwen_max、qwen_plus、qwen_vl）、硅基流动（glm、glm_v、kimi）各自建计划、各自运行，各计划只含本服务商一种币种的上限（第九节）。累计支出加在途上界超过上限时执行器停止该批次，不影响其他服务商的批次。M4 复核需要的对方抽取在评分前由 assemble 跨批次读取。
- 价格以 `configs/rates.json` 为准（预试验所用标价，ds_flash_think 与 ds_flash 同价）。
- `runs/` 下原始记录不手工删改，不回填时间；评分只读冻结后的观测。

## 八、真实报价集

- 单元清单、盲标名单与规范按第十节哈希冻结。盲标子集 15 个单元由标注人 A（新队友）、B（用户）独立标注，整理原件的队友裁决；其余单元由 Claude 初标、A 逐字段复核（分工见规范第八节）。
- 真实报价集的模型运行在全部标签与裁决完成并记录哈希之后进行。运行范围：6 个配置各对每个单元的匿名原件做一次抽取（与 M2–M4 相同的抽取提示词，PDF 与网页正文按文字输入），不运行 M0、M1。
- 计分：主结果为各配置自身抽取经归一化与出处核对后的字段准确率；M4 复核合并后的条款状态（conflicting、missing）作为次要结果描述。原文不进入任何提示词或词表。
- 报告字段完全一致率、状态类字段的 Cohen's κ，准确率置信区间按原件整簇 bootstrap。image 原件数为 0，盲标分层的 image 层按实有数量处理（规范第五节）。
