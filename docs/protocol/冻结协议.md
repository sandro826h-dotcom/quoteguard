# QuoteGuard 正式实验冻结协议

本协议规定正式实验的数据、配置、方法、终点、统计、执行与停止规则。冻结后按本协议执行；任何偏离写入 `docs/protocol/偏离记录.md`，注明日期、原因与影响，不改本文件。冻结时本文件的 sha256 记入 `docs/protocol/冻结记录.md` 与 PROJECT_LOG。

## 一、依据文件

下列文件在冻结时的 sha256 列于第十节，执行以这些版本为准：

- `docs/plan/AIC_最终方案.md`：方法阶梯、实验、主终点与事前决策规则（第六、七节）。
- `docs/plan/任务生成规格.md`：任务层级、约束、标准答案与冻结方式。
- `docs/plan/方法实现规格.md`：M0–M4 的流水线、复核、输出上限、评分。
- `docs/plan/真实报价集_口径与标注规范.md`：真实报价集的计数、纳入、标注、评分与参照下限。
- 代码：冻结提交（第十节）中的 `src/quoteguard/`、`configs/models.yaml`、`data/taskgen/`（v4）、`data/params/tariff_snapshot_2026-10-09.json`。提示词以 `src/quoteguard/prompts.py` 为准。

## 四、方法

- M0、M1、M2、M3、M4 按方法实现规格第五节。M4 对全部候选合并复核方已有的抽取，不另发请求。
- M4_trig（只复核满足风险触发条件的候选）由同一批观测离线生成，只用于 E3，不进入主终点。
- M2–M4 的归一化词表只来自开发池模板与事先写定的通用词表；测试池措辞上的词表覆盖率单独报告。

## 五、终点与统计

主终点三项为一个 Holm 族，族内总体 α = 0.05（方案第七节）：

1. E1 决策正确率（含正确追问）：M4 对 M0，非显式三层 36 个任务，6 个配置合并。统计量为合并后的准确率差（M4 − M0）。置换检验以任务为单位：同一任务在全部配置中的 M0、M4 标签一起交换，保留任务内跨配置的相关；双侧。
2. E2 风险项检出 micro-F1：M4 对 M0，全部 48 个任务，6 个配置合并。统计量为合并后的 micro-F1 差，置换方式同 E1；双侧。
3. 成本主张：低成本档 M4 对同厂商强模型档 M0 的决策正确率（ds_flash 的 M4 对 ds_pro 的 M0，qwen_plus 的 M4 对 qwen_max 的 M0），非显式 36 个任务。统计量为两对准确率差的均值；以任务为单位整簇重抽（bootstrap），p = (1 + #{重抽差 ≤ −0.05}) / (B + 1)，单侧，非劣效界值 −5 个百分点；同时报告重抽差的 5% 分位作为单侧下界。Tango 检验只作敏感性分析。

- 置换检验：任务数不超过 16 时精确枚举，否则蒙特卡洛，p = (1 + 计数) / (sims + 1)。
- 评分命令：`orchestrate score --seed 20261011 --sims 99999 --B 9999`；seed 同时用于全部置换检验与 bootstrap，B 用于全部 bootstrap（含主终点 3 与次要结果的置信区间）。
- 三个主终点的 p 值做 Holm 校正，族内总体 α = 0.05。
- 其余比较为次要结果，只作描述，给按任务整簇 bootstrap 的 95% 置信区间。
- 调用最终失败（第七节）的处理对所有方法相同：该配置、方法、任务的输出记为决策错误、风险项未检出，不从分母中剔除；核价误差记为缺失并单独计数。最终失败包括：无有效观测、返回为空、抽取响应整份解析不出 JSON；输出依赖的调用包括本方法自身调用、本配置各候选的抽取与转写，以及 M4 合并所需的复核方抽取与转写。字段级的解析失败按方法实现规格记为 missing，不算调用失败。失败数按配置与方法报告。

按方案第七节“事前决策规则”表执行，结果出来后不改主线。

## 七、执行

- 顺序：先运行全部转写，再运行 M0、M1、抽取；同一服务商内按任务编号顺序；不同服务商可并行。
- 重试：客户端按现行设置自动重试（`max_retries` = 2，网关类 5xx 至多 1 次）。同一服务商连续 5 次失败时该批次停止。
- 续跑：批次因额度、余额、预算或连续失败停止后，排除原因（换 key、充值、网络恢复）并在同一批次目录续跑；已有有效观测的请求跳过，其余请求（含已失败的）重新发出。每个批次因连续失败续跑至多 2 次。
- 补跑：批次正常结束后，用 `scripts/make_retry_plan.py` 对仍无有效观测的请求生成补跑计划（run_key 不变），以 `<原批次>-retry` 运行一次；仍失败的记为最终失败。同一 run_key 有多份有效观测时取最早的一份。
- 转写阶段（含其续跑与补跑）全部结束后才生成抽取与 M0、M1 的计划，保证提示词哈希一致。
- 千问免费额度用完（HTTP 403，`AllocationQuota.FreeTierOnly`）：停止该批次，保存已完成记录，报告需要更换百炼 key；不重试、不换模型，换 key 后从断点续跑。
- 硅基流动余额不足：同上处理，报告需要充值。
- 批次按服务商划分：DeepSeek 官方（ds_pro、ds_flash、ds_flash_think）、阿里云百炼（qwen_max、qwen_plus、qwen_vl）、硅基流动（glm、glm_v、kimi）各自建计划、各自运行，各计划只含本服务商一种币种的上限（第九节）。累计支出加在途上界超过上限时执行器停止该批次，不影响其他服务商的批次。M4 复核需要的对方抽取在评分前由 assemble 跨批次读取。
- 价格以 `configs/rates.json` 为准（预试验所用标价，ds_flash_think 与 ds_flash 同价）。
- `runs/` 下原始记录不手工删改，不回填时间；评分只读冻结后的观测。

## 八、真实报价集

- 单元清单、盲标名单与规范按第十节哈希冻结。盲标子集 15 个单元由标注人 A（新队友）、B（用户）独立标注，整理原件的队友裁决；其余单元由 Claude 初标、A 逐字段复核（分工见规范第八节）。
- 真实报价集的模型运行在全部标签与裁决完成并记录哈希之后进行。运行范围：6 个配置各对每个单元的匿名原件做一次抽取（与 M2–M4 相同的抽取提示词，PDF 与网页正文按文字输入），不运行 M0、M1。
- 计分：主结果为各配置自身抽取经归一化与出处核对后的字段准确率；M4 复核合并后的条款状态（conflicting、missing）作为次要结果描述。原文不进入任何提示词或词表。
- 报告字段完全一致率、状态类字段的 Cohen's κ，准确率置信区间按原件整簇 bootstrap。image 原件数为 0，盲标分层的 image 层按实有数量处理（规范第五节）。

## 附录：执行命令序列

各命令前设 `export PYTHONPATH=src`。记号：T = `data/tasks/test/tasks`，G = `data/gold/test`，W = 计划目录，F = 实验名 `formal`，H = 本协议冻结哈希；P 取 deepseek、dashscope、siliconflow，C 为该服务商的主配置（deepseek：ds_pro,ds_flash；dashscope：qwen_max,qwen_plus；siliconflow：glm,kimi，视觉配置随主配置进入计划）。

```
E="--experiment F --kind formal --rates configs/rates.json --protocol-sha256 H --seed 20261010"
# 转写（A 阶段）
python -m quoteguard.orchestrate plan --tasks T --configs C --methods M0,M1,M2,M3 --tag P --budget <本服务商单币种上限> --out W $E
python -m quoteguard.orchestrate run --plan W/plans/F-P-A.json --mode live --batch-id P-A --confirm-budget <上限>
python scripts/make_retry_plan.py runs/P-A --out W/plans/F-P-A-retry.json      # 有失败时
python -m quoteguard.orchestrate run --plan W/plans/F-P-A-retry.json --mode live --batch-id P-A-retry --confirm-budget <上限>
# M0、M1、抽取（B 阶段），在本服务商转写及其补跑全部结束后生成计划
python -m quoteguard.orchestrate plan --tasks T --configs C --methods M0,M1,M2,M3 --tag P --budget <上限> --out W --transcriptions runs/P-A[,runs/P-A-retry] $E
python -m quoteguard.orchestrate run --plan W/plans/F-P-B.json --mode live --batch-id P-B --confirm-budget <上限>
python scripts/make_retry_plan.py runs/P-B --out W/plans/F-P-B-retry.json
python -m quoteguard.orchestrate run --plan W/plans/F-P-B-retry.json --mode live --batch-id P-B-retry --confirm-budget <上限>
# 思考组：只跑 B 阶段，复用 DeepSeek 的转写
python -m quoteguard.orchestrate plan --tasks T --configs ds_flash_think --methods M1 --tag think --budget <上限> --out W --transcriptions runs/deepseek-A[,runs/deepseek-A-retry] $E
python -m quoteguard.orchestrate run --plan W/plans/F-think-B.json --mode live --batch-id think-B --confirm-budget <上限>
# 组装与评分
python -m quoteguard.orchestrate assemble --tasks T --gold G --batches <三家全部 A、B 及补跑批次> --configs ds_pro,ds_flash,qwen_max,qwen_plus,glm,kimi --methods M0,M1,M2,M3,M4,M4_trig --experiment F --seed 20261010 --out runs/derived/formal
python -m quoteguard.orchestrate assemble --tasks T --gold G --batches <DeepSeek 的 A 批次与 think-B 批次> --configs ds_flash_think --methods M1 --experiment F --seed 20261010 --out runs/derived/formal_think
python -m quoteguard.orchestrate score --outputs runs/derived/formal/outputs --gold G --tasks T --endpoints --seed 20261011 --sims 99999 --B 9999
```

- 补跑只针对无有效观测、返回为空或 valid 为假的请求；有返回但解析失败的响应不补跑。同一 run_key 有多份有效观测时取最早完成的一份。
- 各服务商批次的上限按 `预算估算.md` 的执行器上限列。
