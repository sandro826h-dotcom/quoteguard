# 补充预注册：两条零费用离线基线

本文件在冻结协议之后、正式实验组装评分之前写定，用户于 2026-10-12 决定采用。写定时正式实验尚未组装评分（`runs/derived/` 下没有 formal 目录），测试集金标签未被查看。两条基线都从正式实验已有的观测离线计算，不发任何模型请求，不改冻结协议规定的方法、提示词、主终点与统计。结果只作探索性分析，不进入主终点的 Holm 族，报告中写作“评分前补充预注册的探索性对照”。本文件的 sha256 与提交时间记入 `偏离记录.md`。

## 一、要回答的问题

1. M4 的追问判断（在缺失或冲突条款的取值网格上检验最优解是否改变）比“有缺口或冲突就追问”的朴素做法多带来多少决策正确率，误拒（不需要追问时追问）减少多少。
2. 完整的到仓成本计算与门控，比卖家常用的“按标价最低选择”多带来多少决策正确率。

## 二、基线定义

两条基线按配置计算，6 个主配置（ds_pro、ds_flash、qwen_max、qwen_plus、glm、kimi）各一份，48 个测试任务全部计算。

### BL_ASK：朴素拒答

- 输入：同一配置、同一任务的 M4 输出（`runs/derived/formal/outputs` 中由 assemble 生成的 M4 文件），即经出处核对并与复核方抽取合并后的各报价条款状态。
- 规则：任一报价的 `per_cand.conflicts` 或 `per_cand.gaps` 非空时，decision = ask，ask_fields 为全部报价上这些字段的并集（写成 `C<k>.<字段>`）；全部报价都没有冲突与缺口时，decision、choice 沿用 M4。
- 其余字段（per_cand 的成本、隐含费用、冲突、缺口、包税风险、资质状态）原样沿用 M4。BL_ASK 与 M4 只在决策规则上不同。

### BL_PRICE：按标价最低选择

- 输入：同一配置、同一任务的首次抽取（M2 使用的抽取，不含复核方抽取），按 `methods_pipeline.normalize` 归一化。
- 标价：取报价 `rate_tiers` 中适用于本票实重（各箱毛重之和）的档位单价，即 min_kg 不大于实重的档位中 min_kg 最大的一档；`rate_tiers` 为冲突状态时取第一个值。单价单位为 per_kg 时标价 = 单价 × 实重，为整票价时标价 = 单价；USD 按任务参数快照的汇率折算为人民币。不计体积重、最低计费重、进位、附加费、燃油、报关、清关、关税、包税门控与时效。
- 规则：从能算出标价的报价中选标价最低者，并列时取任务中排序靠前者；decision = choose，从不追问。没有任何报价能算出标价时，decision = ask，ask_fields 为空。
- per_cand 只填 `cost_cny`（填标价），其余为空。

### 失败处理

基线的来源输出带有 `failed_calls` 时，基线输出继承该字段，按冻结协议第五节对所有方法相同的规则计分（决策错误、风险项未检出、不从分母中剔除）。

## 三、评分

- 每条基线输出按 `metrics.score_task` 评分，method 分别记为 BL_ASK、BL_PRICE，规则与正式方法相同（决策正确含正确追问，追问需覆盖至少一个金标签追问字段）。
- 报告的指标：
  1. 决策正确率：非显式三层 36 个任务与全部 48 个任务，6 个配置合并，另按配置、按层级列出。
  2. 误拒率（金标签为推荐时追问）与漏问率（金标签为追问时推荐）。
  3. BL_PRICE 的决策遗憾（元/票与占最优成本的比例）与选中可行集外报价的比例，口径同方案第五节决策规则第 4 条。
- 风险项 micro-F1 不作为基线指标：BL_ASK 的风险项与 M4 相同，BL_PRICE 不输出风险项。

## 四、比较与统计

- 比较三对：M4 对 BL_ASK、M4 对 BL_PRICE、M0 对 BL_PRICE，统计量为 6 个配置合并后的决策正确率差，在非显式 36 个任务上计算，48 个任务的结果并列报告。
- 置信区间：以任务为单位整簇 bootstrap 的 95% 区间，B = 9999，种子 20261011（与冻结协议第五节评分命令相同）。
- 不计算 p 值，不进入主终点的 Holm 族，结论措辞为描述性。
- 计算与主终点在同一次评分中进行，读同一份 assemble 输出；基线计算代码放在结果流水线中，提交时记录提交号。

## 五、结果解读

- 不设事前决策规则，不因基线结果改动方案第七节的主线判定。
- 三对比较的结果全部在报告中列出。
