# 反事实任务生成与渲染规格（2026-10-10）

依据 docs/plan/AIC_最终方案.md 第四、五节。本规格是协议的组成部分，测试集冻结时一并记录哈希。

## 一、模块划分

| 模块 | 职责 |
|---|---|
| `src/quoteguard/gate.py` | 包税三档判定、资质证据状态判定（确定性规则，M3/M4 与标准答案共用） |
| `src/quoteguard/decide.py` | 决策规则：可行集、最优解、追问判定、决策遗憾 |
| `src/quoteguard/taskgen.py` | 生成发货任务、候选报价条款、层级操作、标准答案 |
| `src/quoteguard/render.py` | 把候选报价渲染成文字、表格、图片，并输出每个字段的原文位置 |
| `data/taskgen/structures.yaml` | 费用结构库：各运输方式的价格档、最低计费重、计泡系数、附加费等取值范围，每项注明取自哪些真实报价单元 |
| `data/taskgen/value_sets.yaml` | 每类可能缺失或冲突的条款的有限取值集合 |
| `data/taskgen/registry_synthetic.yaml` | 反事实任务用的合成登记库快照（全部标注 is_synthetic） |

## 二、gate.py

`ddp_check(shipment, terms, snapshot, freight_floor) -> DDPResult{level: "none"|"verify"|"high", floor_cny_per_kg, quote_cny_per_kg, docs_to_request: list[str]}`
- 只对 `is_ddp=True` 的报价判定，其余返回 `none`。
- 税费下限 = （关税 + MPF，海运加 HMF）÷ 整票计费重，元/kg；关税、MPF、HMF 用 calc_py 的同一口径（DDP 豁免前）。
- 包税单价 = 报价的确定成本 ÷ 整票计费重（含该报价自身列出的附加费）。
- `high`：包税单价 < 税费下限；`verify`：包税单价 < 税费下限 + `freight_floor[mode][dest_zone]`；否则 `none`。
- level 不为 none 时 `docs_to_request` = ["进口商主体（IOR）名称", "CBP 7501 报关单", "申报价值发票"]，海运另加 "ISF 申报确认"。
- `freight_floor` 由参数快照提供；值缺失时抛错，不默认为 0。

`claim_status(claim, channel_mode, registry, quote_entity) -> "supported"|"insufficient"|"contradicted"|"irrelevant"`
- 按 AIC_最终方案.md 第四节第 4 条：未写管辖地时两库都查，任一命中为 supported；两库都未命中为 insufficient；登记库记录与宣称内容不符（如执照已注销、类型不同）为 contradicted；空运或快递渠道援引海运执照、认证主体与报价主体不一致、以中国海关高级认证证明美国清关能力，为 irrelevant。

## 三、decide.py

`decide(task_view) -> Decision{type: "choose"|"ask", choice, opt_cost_cny, ask_fields: list[str]}`
- 可行集：`transit_days` 上限 ≤ 任务时效约束，且 `ddp_check` 不为 high。
- 在可行集内取确定成本最低者；可行集为空时 type=ask。
- 追问判定：对每个缺失或冲突的条款，在 `value_sets.yaml` 给出的取值集合上（多项同时缺失取笛卡尔积）逐一计算最优解；只要最优解在网格上发生变化，type=ask，`ask_fields` 列出这些条款；否则 type=choose。
- `regret(choice, gold)`：选中可行集外报价返回 `out_of_feasible`；gold 为 ask 时返回 None；否则返回（元/票，比例）。

## 四、taskgen.py

`generate(n_per_layer, split, seed, snapshot, structures, value_sets, registry, template_pool) -> list[Task], list[Gold]`

货物：
- 商品四选一：6109.10.00（棉制 T 恤）、3926.90.99（塑料手机壳）、4202.92.31 后缀 31（化纤旅行袋）、9503.00.00（玩具）。单价、件数、箱规取值范围写在 structures.yaml。
- 目的地：FBA 仓代码、邮编、是否偏远，取自 structures.yaml 中的列表（公开仓库代码）。
- 发运日期在 2026-10-12 至 2026-10-31 之间；时效约束 deadline_days 按运输方式设定。

候选：每个任务 4–6 个，运输方式与费用结构从 structures.yaml 抽取；至少 1 个包税候选，至少 1 个不包税候选；资质宣称按比例出现。

层级操作（每个任务只施加本层的操作，层间互不叠加）：
- explicit：全部条款写在正文。
- implicit：至少 1 个会影响最优解的费用放在脚注、附表或附加费表（`fee_location`），条款本身为 stated。
- conflict：至少 1 个候选的 1 个条款在两处给出不同值（status=conflicting）。决定性任务要求两种取值下最优解不同；非决定性任务要求相同。
- insufficient：至少 1 个候选缺 1–2 个条款（status=missing）。决定性与非决定性的判定同上，用 decide.py 在取值网格上验证。

约束（不满足就重抽，最多 200 次，失败则报错）：
- 推荐类任务的最优解与次优解相差不少于 3%；决定性任务的网格上每个取值都满足这一条。
- 每层决定性与非决定性的数量：测试集每层 8 和 4，开发集每层 4 和 2（只对冲突层与信息不足层）。
- calc_py 与 calc_xlsx 对每个候选的确定成本差额不超过 0.01 元（验证步骤单独运行，结果写入 Gold.calc_hashes；不一致就报错，不剔除）。

标准答案（Gold）：每个候选的成本明细、隐性费用编号、冲突与缺口编号、包税等级、资质证据状态；任务决策（choose 或 ask）、最优成本、应追问的条款。

确定性：同一 seed、同一输入文件生成完全相同的任务与答案；任务文件和答案文件分开存放，答案文件不进入任何模型输入。

### 缺口与费用写法的口径

- **必需条款**（与真实报价集规范第九节一致）：所有运输方式为 `rate_tiers`、`dim_divisor`、`min_kg_shipment`、`validity`、`excludes`、`ddp`；快递另加 `fuel_pct`；海运另加 `isf_fee_cny`。必需条款没有写出即为缺口。必需条款取值为 0 时用自然说法写出（如“不设最低计费重”“不收燃油附加费”），不省略。
- **可选费用**（报关费、单箱最低计费重、非海运的 ISF、非快递的燃油、各项附加费）：取值为 0 或不适用时不写，标准答案按 0 或不适用计算，不算缺口。
- 信息不足层的缺失操作只作用于必需条款；冲突操作可以作用于任何条款。
- 包含项与不含项中的税项（关税、MPF，海运另有 HMF）由 `ddp.scope` 决定：scope 为 duty 时包含项只列关税；duty_mpf 列关税与 MPF；all 列关税、MPF，海运另列 HMF；不包税时这些税项都列入不含项。空运与快递报价不出现 HMF。`ddp` 缺失或冲突时，包含项与不含项中不出现任何税项，避免从别处推出真值。
- 报价抬头或落款写出报价主体名称（`quote_entity`），资质宣称中的主体名称与之分开写。

### 标准答案与生成约束的补充规则

- **信息不足层可缺失的条款**：快递为 `dim_divisor`、`min_kg_shipment`、`ddp`、`fuel_pct`；空运为 `dim_divisor`、`min_kg_shipment`、`ddp`；海运为 `dim_divisor`、`min_kg_shipment`、`ddp`、`isf_fee_cny`。generate 按此清单校验。
- **冲突中的 0 值**：冲突的一侧为 0 时，渲染器用自然说法写出（如“不收报关费”），保证两处取值都可见。
- **端到端检查**：生成后对每个缺口候选调用渲染器，冲突字段必须有两个出处，缺失字段必须没有出处，且缺失或冲突的取值不能由其他已写明的字段推出（如包含项与不含项中的税项）。检查不通过即重抽。
- **逐候选标签的“未定”**：缺口候选的成本、包税等级、可行性在取值网格上随取值变化时，金标记录网格上的成本区间、等级集合与可行性集合，并标为“未定”；E2 的包税风险指标与核价误差只在“已定”的候选上计算，“未定”候选单独报告。
- **决策遗憾**：正确答案为追问的任务先判定为不计遗憾，再判断是否选中可行集外报价。
- **包税条款占比**：冲突层与信息不足层中，以 `ddp` 为决定字段的决定性任务不超过该层决定性任务的 40%；非决定性任务中放入同等比例的 `ddp` 缺口。结果按缺口字段分组报告。
- **重抽上限**：每个任务最多重抽 2000 次；仍失败时整个生成报错，不更换 seed，按协议记录并修正生成器后整体重新生成。记录每层重抽次数与被吞掉的异常次数。
- **隐性费用**：隐含层只选本票金额为正的费用作为隐性费用。
- **资质**：dev 与 test 使用互不重叠的合成主体名单；增加“未备案主体宣称交通部无船承运备案”场景。面向模型的登记库快照只包含登记记录，不包含生成器的辅助名单（如未登记主体列表）。
- **面向模型的输入**：由独立的输入构造模块生成，只读取渲染结果（文字、表格的文本视图，图片报价只给 PNG）与白名单内的货物字段（箱规、货物、目的地、时效约束、发运日期）。任务文件中的层级、各字段 status、conflicts、fee_location、模板编号、种子、来源单元编号一律不进入模型输入。冻结时把面向模型的输入单独落盘，计入 manifest 哈希，并用禁用词测试检查。
- **manifest**：生成器代码哈希覆盖 gate、decide、taskgen、calc_py、calc_xlsx、schema、params、util、render；另记 git 提交号、工作区是否干净，以及 Python、PyYAML、LibreOffice 版本。

### 冻结前补充的约束

- 信息不足层按缺口数量分层抽样：决定性与非决定性任务的缺口数量分布相同（各含 1 个、2 个缺口的任务比例一致），避免“缺口多就追问”的捷径；结果按缺口数量与运输方式分组报告。
- 报价未写税务条款时，即使能从价格水平推断是否包税，正确答案仍按决策规则第 5 条判定（价格不是条款）。
- E2 的包税风险指标在包税等级已定（网格上等级唯一）的候选上计算；成本区间不唯一但等级唯一的候选计入。

## 五、render.py

`render(spec: RenderSpec, outdir) -> RenderResult{files: list[str], text_view: str, span_map: dict[field, list[Span]]}`

RenderSpec 字段：cand_id、terms（QuoteTerms，含各字段 status）、conflicts（字段 → 两个取值）、fee_location（字段 → body|footnote|annex）、modality（text|table|image）、template_id、pool（dev|test）、lang_mix（bool）、ddp_wording_id、claim_wording_id、forwarder_alias。

模板：
- text：聊天式中文报价（可中英混写），纯文本。
- table：xlsx 价格表（openpyxl），另输出同内容的 markdown 文本视图供文本模型使用。
- image：PNG 价格表或中性聊天气泡（matplotlib，Noto Sans CJK 字体），不使用任何即时通讯产品的标识，角落标“合成示例”。
- 开发池与测试池各自有独立的模板集合（措辞、版式、字段顺序、包税表述、资质表述都不同），互不重用。每池每种模态至少 3 个模板。
- missing 的字段不出现在报价中；conflicting 的字段在两处分别写出两个值（例如正文与脚注）。

span_map：每个 stated、implied、conflicting 字段在渲染结果中的位置。text 记字符区间与原文片段；xlsx 记工作表与单元格；image 记像素框与该框内的文字。用于出处核对与转写准确率评分。
