# 真实报价集：计数口径、纳入标准与标注规范（2026-10-10）

本文件规定真实报价集的计数单位、纳入与排除、标注方法、评分方法和时间点。设计依据见 docs/plan/AIC_最终方案.md 第五节。标签格式对应 `src/quoteguard/schema.py` 中的 `SeedQuote` 与 `QuoteTerms`；schema 需补充的字段列在第十节。

## 一、计数单位：报价单元

- 报价单元是同一份保存原件中，一个渠道对一个目的区域给出的一套价格与条款。真实报价集与盲标子集都按报价单元计数。
- 渠道按原文的服务名区分，只取普货渠道；同一服务名下的带电、敏感货另列价格的，不另计单元。
- 目的区域按原文的写法取粒度（如“美西”“邮编 8–9 开头”“ONT8 等特价仓”）。
- 一份原件可拆出多个单元，共用 `source_id`，单元编号为 `<source_id>-u<序号>`，如 `Q16-u1`。
- 一份原件的合格单元超过 3 个时，按原文出现顺序取前 3 个。

## 二、纳入标准（全部满足）

1. 原件已保存（`web_page`、`pdf` 或 `image`），记录 sha256；网页另存整页截图。
2. 记录了采集日期 `captured_at`；原件上可见的发布日期或生效日期记入 `page_date`，看不到时留空。
3. 目的地为美国，运输方式可以识别。
4. 至少有一个可计算的计价项：按 kg 或 CBM 的单价（含重量档）或按票的固定价。
5. 来源公开可访问，不需要登录，不是私聊或付费内容。

## 三、排除

- 没有原件的来源。Q09–Q15（FedEx 价卡）在原 PDF 补齐前排除。
- 只有查价入口、没有数值的来源，例如 Q21。
- 原始出处与发布日期无法核实的转载，例如 Q20；补齐原始出处后可以纳入。

历史价、起价、区间价、表头与数据列数不一致、前后条款矛盾都纳入，按第六、七节标注。

## 四、平衡与数量

- 每个 `source_id` 最多 3 个单元；每个发布主体最多 6 个单元，超出时按 `source_id` 顺序、再按单元序号取前 6 个。
- 承运商公布价（UPS、DHL、FedEx）记 `source_class = carrier_published`，最多 6 个单元，单独报告；货代报价记 `source_class = forwarder`。
- 目标不少于 25 个单元。承运商单元取满 6 个时，货代单元不少于 19 个。低于 25 个时照实报告实际数量。
- 削减下限为 15 个单元，其中货代单元不少于 10 个。
- 同一原件、同一主体的单元共享模板和条款，彼此不独立。报告中写明不同原件数与不同主体数；准确率的置信区间按原件整簇 bootstrap。

## 五、单元清单与盲标子集

- 全部合格单元确定后，先写出清单 `data/seeds/units.json` 并记录哈希，再抽盲标子集。
- 盲标子集 15 个单元，用种子 20261010 按 `source_class` 与原件类型分层抽取，约束如下：
  - 至少 3 个发布主体；
  - 每个主体最多 5 个单元，每份原件最多 2 个单元；
  - `web_page`、`pdf`、`image` 三类原件各至少 3 个单元。合格单元不够时按实有数量抽取，并写明原因。
- 名单写入 `data/seeds/blind_subset.json` 并记录哈希，之后不再更改。

## 六、标签格式

### 元数据

| 字段 | 取值 |
|---|---|
| `seed_id`、`source_id` | 如 `Q16-u1`、`Q16` |
| `source_class` | `forwarder`、`carrier_published` |
| `source_type` | `web_page`、`pdf`、`image` |
| `source_url` | 货代单元在仓库中只写代号（如 `F05-src-1`），真实网址记在仓库外的对照表；承运商单元写真实网址 |
| `captured_at`、`page_date` | ISO 日期 |
| `publisher_alias` | 发布主体代号，货代用 F 编号，承运商用 `UPS`、`DHL`、`FEDEX`；schema 中原有的 `forwarder_alias` 保留，货代单元两者取值相同 |
| `channel`、`dest_region` | 归一化前的原文写法，照抄后做匿名化替换 |
| `price_form` | `published_tier`（分档价）、`starting_price`（起价）、`range`（区间价） |
| `date_status` | 相对 `captured_at` 判断：`current`（在有效期内，或未写有效期且 `page_date` 在 `captured_at` 前 90 天内；有效期只写了起始日、未写截止日，如“起生效至下一期更新”，按在有效期内处理）、`expired`（已过有效期，或未写有效期且日期早于 90 天）、`unknown`（无日期） |
| `modality` | 送入系统的形态：`text`（网页正文）、`pdf`、`image`、`table` |
| `raw_sha256`、`anon_sha256` | 原件与匿名件的哈希 |
| `is_real` | 固定为 true |

### 条款字段

字段集合与 `QuoteTerms` 相同：`channel`、`mode`、`rate_tiers`、`min_kg_shipment`、`min_kg_carton`、`dim_divisor`、`rounding_kg`、`surcharges`、`fuel_pct`、`includes`、`excludes`、`ddp`、`broker_fee_cny`、`isf_fee_cny`、`transit_days`、`validity`、`liability`、`claims`。

每个字段记三项：

- `status`：`stated`（原文直接写出）、`implied`（由明确的表头或注释唯一推出，如表头写“元/kg”）、`missing`（原文没有，value 为空）、`conflicting`（见第七节）。
- `spans`：原文逐字片段。网页与 PDF 用 `kind = text`，PDF 另记页码；图片用 `kind = region` 与像素框 `bbox`。片段与框都以匿名件为准，即片段中的公司名等已按匿名化规则替换。
- `value`：按下表归一化为 schema 类型。原文写法只出现在 spans 中。

| 原文 | 归一化 value |
|---|---|
| 百分数，如“燃油 15%” | 小数 0.15 |
| 重量，如“12KG”“12 公斤” | kg 数值 12 |
| 币种 | 金额写数值，币种写入 `currency`（CNY 或 USD），不换算 |
| 运输方式 | 快递 → `express`；空派 → `air`；海派、海卡、海运拼箱或整柜 → `sea`，原文渠道类型另记在 `channel` |
| 起价 | 记该起价数值，元数据 `price_form = starting_price` |
| 区间价，如“8–12 元/kg” | 记区间下限，上限记入备注 `range_max`，元数据 `price_form = range` |
| 有效期 | ISO 日期对 `[from, to]`，缺一端记 null |
| 按 CBM 或按票计价的档位 | `rate_tiers` 照常记录，档位的 `unit` 记 `per_cbm` 或 `per_shpt`；按柜计价记入备注 `rate_tiers_other`。非按 kg 计价的单元不进入计算与参照下限 |

## 七、歧义的唯一处理规则

- 同一条款在两处给出不同值（如最低计费重一处写 12 kg、一处写 6 kg）：status 记 `conflicting`，value 记两个归一化值的列表，两处都记出处。
- 表头与数据列数不一致：`rate_tiers` 记 `conflicting`，value 记两种对齐方式各自得到的档位列表，出处记表头与数据行。
- 其他无法唯一确定的情况：记 `missing`，写备注，不猜测。

## 八、标注流程与独立性

1. **标注人 A**：对盲标子集的 15 个单元从原件从头标注，不看任何初标。其余单元可以先由 Claude（Anthropic，不属于 6 个实验配置）初标，A 逐字段复核；初标的模型名称与日期写入标签文件。
2. **标注人 B**：只对盲标子集的 15 个单元独立标注。标注时只看匿名件、本规范和 schema 字段定义。
3. 两名标注人都不看待评系统的输出、两套计算器的结果或对方的标签。B 的标签先在仓库外保存，A 的标签写入仓库并记录哈希之后再导入仓库。
4. 分歧由第三人裁决，裁决人不看系统输出；团队没有第三人时，由 A、B 合议并逐条记录理由。裁决记录写入 `data/seeds/adjudication.json`。
5. 全部标签与裁决在真实报价集的模型运行之前完成，并记录哈希。
6. 标签文件路径为 `data/seeds/labels/<seed_id>.<标注人代号>.json`，记录标注日期与用时。
7. 一致性指标：数值与枚举字段报告完全一致率；`status` 同时报告 Cohen's κ 与各状态的一致率。

## 九、系统与金标签的比对

- 参与评分的字段：第六节条款字段全部。
- 字段判为正确的条件：
  - `stated`、`implied`：status 一致，且 value 与金标签完全相等；数值按 Decimal 比较，`rate_tiers` 要求档位逐档相等。
  - `missing`：系统给出 missing。
  - `conflicting`：系统给出 conflicting，且两个值的集合与金标签相等。
- 图片单元先由视觉模型转写为文字，系统出处指向转写文本；图片单元的出处准确率单独报告，判定条件为：片段是转写文本的子串，且与金标签框内文字一致（规则同下）。
- 出处判为正确的条件：系统给出的片段在去除首尾空白、连续空白合并为一个后，是匿名件正文的子串，并且落在金标签出处所在的同一句或同一单元格内。
- 缺口的金标签：按运输方式规定的必需条款中，status 为 missing 的项。必需条款如下：
  - 所有运输方式：`rate_tiers`、`dim_divisor`、`min_kg_shipment`、`validity`、`excludes`、`ddp`；
  - `express` 另加 `fuel_pct`；
  - `sea` 另加 `isf_fee_cny`。
- 真实单元的原文不进入任何提示词或示例。费用结构库从真实单元提炼数值范围，用到的单元记在 `Candidate.base_seed_ids`；用过与没用过的单元，准确率分开报告。

## 十、需要补入 schema 的字段

- `SeedQuote`：`source_id`、`source_class`、`publisher_alias`、`price_form`、`date_status`、`dest_region`。
- `modality` 枚举统一为 `text`、`pdf`、`image`、`table`。
- `RateTier` 增加计价单位 `unit`（`per_kg`、`per_cbm`、`per_shpt`），计算器只接受 `per_kg`。
- 标签记录 `LabelRecord`：status 为 `conflicting` 的字段，value 为候选值列表（长度 2），每个元素按该字段类型校验；含 conflicting 字段的标签不转换为可计算的 `QuoteTerms`。

## 十一、匿名化

- 仓库中只放匿名件：网页把公司名、网址、电话、微信号、地址、信用代码替换为代号；PDF 与图片中的公司名、标识、二维码、电话、地址、信用代码区域加黑框。
- 原件、名称与网址对照表、海关与 FMC 的真实名称查询记录由团队在仓库外保存。

## 十二、不包税运价参照下限

参照表 `freight_floor[mode][dest_zone]` 在测试集冻结前确定，规则如下：

- 纳入单元：`source_class = forwarder`、`ddp.is_ddp = false`、`price_form = published_tier`、`date_status = current`、按 kg 计价。不包税运价不含关税，与 2026-07-24 前后的关税制度无关，因此不按 `page_date` 设日期下限。
- 取值：每个单元取其按 kg 计价的最低一档单价（对货代最有利的价格，使“需核实”档的判定偏保守），再在同一 `mode` 与 `dest_zone` 内取最小值。USD 价格按参数快照汇率换算为人民币。
- `dest_zone`：按目的邮编首位划分，0–3 为美东，4–7 为美中，8–9 为美西；原文只写仓库代码的，按仓库所在邮编归类。
- 海卡单元不进入 `sea` 的参照值，因为海卡的计价方式与海派不同。反事实任务的海运渠道只用海派，海卡只出现在真实报价集的抽取评估中，因此门控不会拿海派参照值去判海卡报价。
- 回退：某个 `mode` 与 `dest_zone` 组合没有合格单元时，用同一 `mode` 的全国最小值；某个 `mode` 完全没有合格单元时，该运输方式不设“需核实”档，只判“高”或不标，并在报告中写明。
- 参照表的每个值记录来源单元编号，写入 `data/taskgen/freight_floor.yaml`。

## 十三、时间点

- 测试集冻结前：完成单元清单、第十二节参照表。按 2026-10-10 复审后的单元清单，只有 Q01 的三个标准空派单元满足纳入条件（美西、美中、美东各一个）；海运与快递没有合格单元，按回退规则不设“需核实”档。
- 协议冻结前（10-11）：单元清单哈希、盲标名单哈希、本规范哈希写入协议。
- 真实报价集模型运行前：全部标签与裁决完成并记录哈希。
