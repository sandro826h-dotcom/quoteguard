# 方法阶梯 M0–M4 实现规格（2026-10-10）

依据 docs/plan/AIC_最终方案.md 第四、六节与 docs/plan/任务生成规格.md。本规格与其中的提示词原文在测试集生成前冻结，是协议的组成部分。

## 一、模块

| 模块 | 职责 |
|---|---|
| `src/quoteguard/inputs.py` | 由任务文件和渲染结果构造面向模型的输入；图片报价的转写 |
| `src/quoteguard/prompts.py` | M0、M1、抽取、转写的提示词模板（原文见第四节） |
| `src/quoteguard/methods.py` | M0–M4 流水线：生成执行计划、读取观测、产出统一的方法输出 |
| `src/quoteguard/locate.py` | 出处核对 |
| `src/quoteguard/questions.py` | 追问清单（按条款模板生成） |
| `src/quoteguard/metrics.py` | 方法输出与标准答案的比对 |

## 二、面向模型的输入（inputs.py）

`build_task_input(task, render_results, pool) -> TaskInput`

- 货物说明：只用白名单字段（品名、运输方式、件数、箱数、每箱尺寸与重量、货值、目的地代码与邮编、地址类型（商业或住宅）、是否偏远地区、时效要求、发运日期），按固定中文模板写成一段文字；非 FBA 地址写“收货地址”，不写“目的仓”。
- 报价：按任务内候选的原有顺序，编号为“报价1”“报价2”……；文字报价用渲染的 text_view；表格报价用 markdown 视图；图片报价只给 PNG。
- 不得出现：层级、各字段 status、conflicts、fee_location、模板与措辞编号、池、种子、来源单元编号、Gold 任何内容、生成器辅助名单。禁用词测试覆盖 layer、explicit、implicit、conflict、insufficient、missing、conflicting、fee_location、footnote、annex、template、status、true_values、gold、dev-、test-。
- 登记库：`gate` 用的面向模型快照（`model_registry_snapshot`）在 M1 中以表格文字给出；M3、M4 由程序直接查询。
- 图片转写：每个配置先用自己的视觉模型（`vision_config_id`）把图片报价转写为文字（阶段 `transcribe`），转写结果作为该配置 M0–M4 的共同输入。GLM-4.5V 输出中的 `<|begin_of_box|>`、`<|end_of_box|>` 标记在转写后删除。转写准确率按字符级编辑距离对照渲染时的 text_view 计算。

## 三、统一的方法输出

```
MethodOutput {
  task_id, method, config_id,
  decision: "choose" | "ask",
  choice: "C1".. | null,
  ask_fields: ["C2.dim_divisor", ...],
  questions: [str],
  per_cand: { "C1": { cost_cny: Decimal|null, ddp_level: "none"|"verify"|"high"|null,
                      claim_status: {claim_idx: status}|null,
                      hidden_fees: [code], conflicts: [field], gaps: [field] } },
  parse_ok: bool, parse_error: str|null,
  calls: [run_key], cost: {USD, CNY}
}
```

报价编号与候选编号的对应由 inputs 记录（报价k → 第 k 个候选），模型输出中的“报价k”映射回候选编号。

## 四、提示词原文

### 转写（所有配置的视觉模型）
```
请逐字转写这张图片中的全部文字。按从上到下、从左到右的顺序输出，每个表格行占一行，单元格之间用“|”分隔。不要总结，不要补充图片中没有的内容。
```

### M0（卖家直接询问）
```
我是做亚马逊的卖家，这票货要从国内发到美国，下面是货的情况和几家货代给我的报价。帮我看看选哪家最划算，有没有什么坑。

【货物】
{shipment_text}

【报价】
{quotes_text}

最后请单独用一行 JSON 给出结论，格式为：{"choice": "报价编号或‘需要追问’", "risks": ["风险1", "风险2"], "questions": ["要问货代的问题"]}
```

### M1（强提示词：检查清单与规则）
```
你是跨境物流成本审计员。请按下列步骤审计每一份报价，再按决策规则给出结论。

【货物】
{shipment_text}

【参数】（日期 {snapshot_date}）
汇率：1 美元 = {fx} 元人民币。
该商品的美国进口关税合计税率：{duty_rate}（MFN {mfn} + 301 清单 {s301} + 新 301 {s301_2026}）。
MPF：正式报关（货值超过 2500 美元）按货值 0.3464%，最低 34.58 美元、最高 670.86 美元；非正式报关 2.77 美元。HMF：仅海运，货值 0.125%。
不包税运价参照下限：{freight_floor_text}

【登记库查询快照】
{registry_text}

【步骤】
1. 逐份列出报价条款：重量档与单价、整票与单箱最低计费重、计泡系数、计重进位、附加费（含脚注与附表中的费用）、燃油、报关费、ISF 费、包税范围与进口商主体、时效、有效期、资质宣称。
2. 找出前后矛盾的条款和缺少的必需条款（重量档、计泡系数、最低计费重、有效期、不含项、包税条款；快递另加燃油；海运另加 ISF）。
3. 计算每份报价的计费重与卖家需支付的确定到仓成本（元），或然费用（如查验费）单列不计入。不包税时卖家另付关税、MPF、海运另付 HMF。
4. 包税报价：税费下限 =（关税 + MPF，海运加 HMF）÷ 计费重。报价自身收费 ÷ 计费重低于税费下限为“高”；低于税费下限加参照下限为“需核实”；否则“无”。
5. 资质宣称：对照登记库快照判定为“有证据”“证据不足”“与宣称矛盾”“与本次运输不相关”（规则见下）。
6. 决策规则：满足时效且包税风险不为“高”的报价构成可行集，选确定成本最低者；若矛盾或缺失的条款在合理取值范围内会改变最优选择，不作推荐，改为追问，并列出要追问的条款。

【计算与判定规则】
- 计费重：每箱取实重、体积重（长×宽×高÷计泡系数）、单箱最低计费重三者中最大者，按计重进位步长向上取整，乘以箱数后求和，再与整票最低计费重取大。
- 重量档：取下限不超过计费重的最高一档，整票按该档单价计。
- 燃油附加费只按运费计。住宅派送费、偏远地区费只在地址条件满足时计入。报价未写出的可选费用（报关费、各项附加费、空运与快递的 ISF 等）按 0 计，不算缺失。
- 关税按货值计，不含运费。包税只免除报价写明的税项，其余税项由卖家另付（例如只包关税时卖家另付 MPF，海运另付 HMF）。
- 快递与海运没有参照下限时，不设“需核实”档。
- 资质：宣称未写管辖地时两个登记库都查，任一库有记录即“有证据”；记录已注销、类型不符或编号不符为“与宣称矛盾”；空运或快递援引海运执照、认证主体与报价主体不一致、以中国海关认证证明美国清关能力，为“与本次运输不相关”；FMC 的无船承运人须为 NVOCC 类型；海关企业信用记录不能证明无船承运业务备案。
- 追问判定中“合理取值范围”指：{value_sets_text}；前后矛盾的条款取原文两个值。

【报价】
{quotes_text}

最后请单独用一行 JSON 给出结论，格式为：
{"choice": "报价编号或‘需要追问’", "ask_fields": ["报价编号.条款名"], "per_quote": {"报价1": {"cost_cny": 数字或null, "ddp_level": "无|需核实|高", "claims": ["有证据|证据不足|与宣称矛盾|与本次运输不相关"], "hidden_fees": ["费用名"], "conflicts": ["条款名"], "gaps": ["条款名"]}}, "questions": ["要问货代的问题"]}
```

### 抽取（M2–M4，每份报价一次调用）
```
请从下面这份货代报价中抽取条款，只抽取原文写明或能由表头唯一推出的内容，不要推测。每个条款给出状态和原文片段。

状态：stated（原文写明）、implied（由表头或注释唯一推出）、missing（原文没有）、conflicting（原文两处写法不同，两个值都给出）。
原文片段必须逐字摘自报价原文。

【报价原文】
{quote_text}

只输出一个 JSON 对象，键为下列条款名，每个值为 {"status": ..., "value": ..., "quotes": ["原文片段"]}：
mode（express/air/sea）、rate_tiers（[{"min_kg": 数字, "price": 数字, "currency": "CNY|USD"}]）、min_kg_shipment、min_kg_carton、dim_divisor、rounding_kg、surcharges（[{"code": 原文费用名, "basis": "per_kg|per_ctn|per_shpt|pct_freight", "amount": 数字, "currency": ..., "condition": "always|residential|remote|ctn_longest_side_gt|ctn_kg_gt", "threshold": 数字或null, "contingent": true/false}]）、fuel_pct（小数）、includes、excludes、ddp（{"is_ddp": true/false, "scope": "duty|duty_mpf|all", "duty_terms": "included|actual|capped", "cap_cny_per_kg": 数字或null, "ior": "forwarder|seller|unspecified"}）、broker_fee_cny、isf_fee_cny、transit_days（[最少, 最多]）、validity、liability、claims（[{"type": 原文资质说法, "entity": 主体, "reg_no": 编号或null, "jurisdiction": "US|CN|null"}]）、quote_entity（报价主体名称）。
conflicting 时 value 为两个值的列表。
```

## 五、流水线

- **M0**：一次调用，输入为货物说明与全部报价；解析末行 JSON。
- **M1**：一次调用，提示词见上；解析末行 JSON。
- **M2**：每份报价一次抽取调用 → 解析为条款（解析失败的条款记 missing）→ 资质类型与附加费名称由词表映射到内部代码（`methods.normalize`，映射不到的保留原文，费用名映射不到时按费用基础计算）→ calc_py 计算确定成本（缺失条款按计算器默认值）→ 可行集只按时效 → 选最低者。M2 不判包税风险、不追问。
- **M3**：M2 加 `gate.ddp_check`（可行集排除“高”）与 `gate.claim_status`（用面向模型的登记库快照）。不追问。
- **M4**：M3 加：
  1. 出处核对：`locate.verify` 检查每个条款的原文片段（去首尾空白、合并连续空白后为报价文本的子串）；片段找不到的条款降为 missing。
  2. 冲突与缺口：抽取为 conflicting 的条款，与必需条款中为 missing 的条款，进入缺口清单。
  3. 风险触发复核：候选存在冲突、缺口、包税风险不为“无”、或资质状态为“证据不足”时，由复核配置对该报价独立抽取一次（低成本档：DeepSeek-Flash 与 qwen-plus 互为复核；强模型档：DeepSeek-Pro↔qwen3.8-max、GLM-5.3↔Kimi-K2.6）。两次抽取对同一条款取值不同时，该条款记为 conflicting。
  4. 决策：用 `decide`，在 value_sets 的取值网格上判断是否追问；追问时由 `questions.py` 按条款模板生成问题。
- 每次调用都经执行器，记录完整；方法输出写入 `runs/<batch>/outputs/<method>/<config>/<task>.json`。

## 六、评分（metrics.py）

- 决策正确：gold 为 choose 时，decision 为 choose 且 choice 等于 gold.choice；gold 为 ask 时，decision 为 ask 且 ask_fields 覆盖 gold 的追问条款中至少一项。
- 决策遗憾：按 `decide.regret`。
- 风险项检出 micro-F1：风险项为（候选，类别，键）三元组，类别为 hidden_fee、conflict、gap、ddp_risk；ddp_risk 的阳性为“需核实”或“高”；只在包税等级已定（gold 的 ddp_levels 只有一个值）的候选上计 ddp_risk。
- M0、M1 的自由文本风险按费用类型词表映射为三元组（`metrics.LEXICON`），映射规则在测试集生成前冻结；人工抽检 20%。
- 资质证据状态准确率；核价误差（已定候选，|cost − gold| 与相对误差）；追问清单覆盖率；转写准确率；每任务调用数、token、费用、时延。

## 七、实现中确定的口径

- 隐性费用（hidden_fee）类别只计召回：方法把该费用计入成本（M2–M4 抽取到且金额为正）或在风险中指出（M0、M1），记为检出；未检出记为漏检；该类别不计误报，因为流水线无法区分费用写在正文还是脚注，正文费用不应算作误报。micro-F1 中误报只来自 conflict、gap、ddp_risk 三类。
- M4 的出处核对：条款给出了片段但全部核对不上时降为 missing；没有给片段的条款保留（预试验后据实际情况决定是否收紧，测试集冻结前定稿）。
- 复核与首次抽取不一致：两边都有值且不同记 conflicting；必需条款一边缺失时保持 missing；可选费用一边缺失时按 0 比较。
- M4 无法核价（rate_tiers 或 transit_days 缺失）时追问这些条款；M2、M3 把该报价排除出可行集，可行集为空时输出追问且 ask_fields 为空。
- M2、M3 缺计泡系数时按快递 5000、空运与海运 6000 计算，缺计重进位按 1 kg，记入 defaulted。
- 含冲突条款时，M2、M3 取两值中成本较低者计算并记录；M4 对有缺口的候选同样报出默认值下的成本，以便与 M2 的核价误差比较。
- M0 的追问条款：M0 输出“需要追问”或条件式回答（含多个报价编号或“如果”“若”等条件词）时判为追问；追问条款由其 questions 与 risks 文本经冻结词表映射为“候选.条款”。M1 的 ask_fields 为空或映射不到时用同一词表兜底。
- 流水线（M2–M4）只要输出了决策就按决策计分，单份报价抽取解析失败按该报价条款缺失处理，解析失败率单独报告；M0、M1 无法解析时按错误计。
- 主终点 1、2 的置换以任务为单位：同一任务在 6 个配置下的方法标签一起交换。主终点 3 以按任务整簇 bootstrap 为主检验，Tango 检验为敏感性分析；结论以 Holm 校正后的结果为准。
- 复核：复用复核方已有的首次抽取，不另发请求；被复核配置的成本计入所用复核抽取的费用。每个配置的单次审计成本计入全额转写费用（独立部署时需要支付）；共用视觉模型时实际总支出另行汇总。复核方的抽取以复核方自己的转写为原文做出处核对。
- 输出上限：M0 4000 token，M1 8000 token，抽取 2500 token；预试验统计截断（finish_reason 为 length）的比例。
