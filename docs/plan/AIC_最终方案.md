# AIC「AI+跨境电商」最终方案：QuoteGuard 运价明镜（2026-10-09）

本文件取代 AIC_选题方案.md 中的方向设计。比赛规则的核对仍以 AIC_选题方案.md 第二节为准。

## 〇、一句话

QuoteGuard 帮中国跨境卖家审计美国头程物流报价，报价可以是微信文字、Excel 或价格表图片。系统做五件事：
1. 把报价折算成可比的到仓成本；
2. 找出隐性费用和前后矛盾的条款；
3. 核查“包税”报价和资质宣称有没有依据；
4. 信息不足时不给推荐，改为生成追问清单；
5. 输出一份可以核对的决策报告（“决策护照”）。

用一套可复算的评测集，把它和卖家现在的做法比较。卖家现在的做法是把报价贴给通用大模型问“哪家划算”。

## 一、选题与定位

- **作品名称**：运价明镜：跨境头程报价智能审计（15 字）。英文名 QuoteGuard。
- **使用者**：中国跨境电商卖家，以亚马逊 FBA 卖家为主，向美国发头程货（快递、空派、海派包税专线）。
- **部署形态**：独立工具，也可以作为卖家 ERP 的插件或货代比价平台的审核模块。
- **对应官方方向**：
  - 方向四：多仓协同物流与合箱优化；
  - 方向二：报关通关；
  - 方向三：账号健康与合规风控。

## 二、为什么最终定这个题（按评委视角对前几版做的自查）

QuoteGuard 前一版的设定是海外买家向中国供应商采购。这一版有五个问题，之前没有人指出：

1. **视角不对**：使用者是海外买家。中国评委理解的“AI+跨境电商”以中国卖家出海为主。
2. **需求证据弱**：只有 Accio 的用户规模可以引用，Accio 是否做报价比较也没有核实。
3. **证据实验只能用合成数据**：资质证书没有公开库，信任实验必然被质疑。
4. **细节容易被抓**：马来西亚的税费与 ST 管制规则都没有核实，有贸易背景的评委容易在细节上挑错。
5. **场景不够真实，输出没有落到行动**：真实 B2B 采购以询价和谈判为主，“让 AI 直接选供应商”这个场景不够真实；系统也没有给出可执行的输出，例如追问清单、应当索要的单证。

头程报价这个题针对上述问题逐条改进：

| 维度 | 头程报价审计 |
|---|---|
| 使用者 | 中国卖家，切题 |
| 需求证据 | 法院白皮书、海关数据、真实货代报价中的“不含项目” |
| 真实数据 | 承运商官方规则、公开的货代价格页，以及可以人工查询的资质登记库 |
| 时效性 | 2025–2026 年美国关税与小额豁免规则多次变化，报价口径随之混乱 |
| 现有工具 | 没有见到同时覆盖中文非结构化报价、包税条款歧义、资质核验和 FBA 渠道的工具 |

## 三、需求论证（已核实的证据链）

1. **纠纷集中在运费**
   - 宁波海事法院白皮书（2024-11）统计了 2021 年至 2024 年 6 月结案的跨境电商物流案件，共 400 件，标的额 1.58 亿元。
   - 争议焦点中，代理运费占 79.3%；目的港为美国的占 74.5%。
   - 这类案件占货代与多式联运案件的比例，从 9.8% 升到 52.2%。
2. **规则多次变化**（税率与生效日期以 USITC HTS 2026 Rev 20 和 Federal Register 原文为准）
   - 2025-08-29：美国暂停所有国家的小额豁免。
   - 2026-02-20：最高法院判定 IEEPA 关税无效，CBP 自 2026-02-24 起停征。
   - 2026-02-24 起开征第 122 条临时关税（HTS 9903.03.01，加征 10%），2026-07-23 日终到期（HTS 第 99 章编者注，91 FR 9339）。
   - 2026-07-24 起，新的 301 关税对中国产品加征 12.5%（HTS 9903.05.31，91 FR 47318）。按 HTS 第 99 章 U.S. note 52(a)，这项关税与原有对华 301 关税叠加。
   - 原有对华 301 关税继续有效（91 FR 64212）；232 关税继续有效。
   - 2026-10-08：CBP 发布 Low-Value Shipments 拟议规则，修改货值 2,500 美元以下非正式报关的申报要求。
   - 2027-07-01 起，小额豁免在法律上永久废除。
3. **执法收紧**
   - 截至 2025-12，CBP 已对 2.46 亿多件原免税小包征税超过 10 亿美元。
   - 2026 年卖家社区报道了 5H、9H 扣货；有卖家因低申报被要求补交多票单证（报道来源为雨果网）。
4. **报价本身含隐性费用**
   - 公开的包税报价通常把以下项目列为“不含”：查验产生的仓储或滞港费、扣货损失、私人住宅派送费、高货值加价。
   - 有货代自己承认，低价包税多走低申报渠道。
   - 货代空派、海派按 ÷6000 计泡，快递按 ÷5000 或 139 in³/lb 计泡，口径不一致。
5. **卖家感知**
   - Jungle Scout 2025 年调研中，38% 的卖家把运费上涨列为主要挑战。这项调研的样本不专指中国卖家。
6. **工具空白**
   - Freightos、亚马逊 AGL、5688 运价 API 提供结构化报价或订舱，包税条款只写在自由文本里。
   - Flexport 的 MCP 只能查自家运价。
   - CostClaw 做报价归一和发票审核，面向英文海运进口商。

需求分析不发问卷、不做访谈，证据来自官方与司法统计、真实报价样本、工具对照和本项目的实测。如果有卖家试用并写反馈，可以放进佐证材料，但方案不依赖这一项。

## 四、系统设计

1. **多模态抽取与原文定位**
   - 输入：微信文字、Excel 或 CSV、价格表图片或 PDF。
   - 抽取字段：渠道、计费方式（单价阶梯、最低计费重、计泡系数）、包含与不含项目、附加费、时效、包税范围、清关方式与进口商主体（IOR）、赔付条款、有效期。
   - 每个字段都保留出处（原文片段、表格单元格或图片区域），并用脚本核对出处确实存在于原文中。
2. **冲突与缺口识别**
   - 冲突示例：报价写“双清包税”，备注却写“关税实报实销”。
   - 缺口示例：没有写计泡系数；没有写私人地址附加费；没有写有效期。
3. **确定性核价**
   - 输入货物参数（件数、尺寸、重量、货值、品名及其 HTS 税率快照）和报价条款，输出每票和每件的到仓成本。
   - 成本构成：运费（计费重 × 阶梯单价，含整票最低计费重、单箱最低计费重、计重进位）、附加费、关税、MPF、HMF（海运）、报关费，海运另计 ISF 费用。查验费、滞港费等或然费用单列为“风险敞口”，不计入确定成本。
   - 完税价格按货值（成交价格）计，不含国际运费。
   - 承运商官方表只用于计泡、超尺寸与超重、偏远地区、燃油附加费四项，燃油按周快照。FBA 仓是商业地址，住宅附加费只在目的地为住宅地址时计入。货代协议价以报价自身条款为准，官方附加费作为“如果转嫁”时的参照。
   - 两套独立实现交叉核对标准答案：A 为 Python 计算引擎；B 为带公式的 Excel 工作簿，由 LibreOffice 重算后读回。另由人工手算 5 个任务留档。两套实现按同一份书面规格分别编写；两者差额超过 0.01 元的任务必须排查并修正到一致，不以剔除代替修正，确实无法修正而剔除的任务数如实报告。共同规格本身的错误由 5 个手算任务发现。
4. **风险与证据门控**
   - **包税合理性**：按三档判定，事前写入协议。货值用卖家给出的真实货值。
     - 税费下限 = （关税 + MPF，海运加 HMF）÷ 该报价的整票计费重，单位元/kg。
     - 高：包税单价低于税费下限，即报价连税费都不够；
     - 需核实：包税单价低于“税费下限 + 不包税运价参照下限”。参照下限取参数快照中带日期的参照表 `ddp_freight_floor[运输方式][目的区域]`，取值为真实报价集中同运输方式、同目的区域不包税报价的最小值；
     - 其余不标。
     - 可行集保留“需核实”档报价；它成为最优解时，正确做法是推荐并列出应当索要的单证。
     - 标出风险时列出应当索要的单证：进口商主体（IOR）名称、CBP 7501 报关单、ISF 申报确认、申报价值发票。IOR 是卖家本人时，卖家作为 IOR 承担申报责任（19 USC 1592）。系统只标风险，不判定货代违法。
   - **资质宣称**：例如“NVOCC”“海关高级认证”。宣称与登记库查询快照比对（FMC OTI 名单、海关企业信用公示平台），状态分四种：有证据、证据不足、证据与宣称矛盾、证据与本次运输不相关。判定规则：
     - 宣称未写明管辖地时，两个登记库都查：任一库命中记“有证据”并注明管辖地，两库都未命中记“证据不足”。国内交通运输部的无船承运备案与美国 FMC 执照是两种资质，结论中分开写明。
     - 空运渠道援引海运执照、认证主体与报价主体不一致，或以中国海关高级认证证明美国清关能力时，记“不相关”。
     - 反事实任务使用的登记库快照是合成的，单独标注。真实报价集的名称对照表不公开，真实集的证据状态只能由项目组复核，公开材料无法复算。
5. **风险触发复核**
   - 触发条件：存在冲突或缺口、包税不合理、证据状态不确定、多模型意见分歧。
   - 复核方式：另一家模型独立抽取，或者把候选重新排序后再判断。
   - 只在触发时追加调用，并记录额外成本。
6. **决策护照与追问清单**
   - 决策护照列出：可比成本、隐性费用、风险项、证据状态、推荐理由。
   - 信息不足时不作确定推荐，改为生成可以直接发给货代的追问清单。

## 五、数据与评测集

**真实报价集**
- 收集 30–50 份公开的货代价格页或价格表，图片、表格、文字各不少于 10 份，注明来源和抓取日期，按实际模态分布报告。只做人工逐条记录，不批量抓取，不用需登录的内容和私聊内容。
- 匿名化：货代编为 FWD-xx；图片中的名称、标识、电话、微信号、二维码、地址、信用代码做遮盖；原件与遮盖件分别记哈希；名称对照表和真实名称的登记库快照不进仓库。
- 标注：标注指南冻结后，云端会话初标并给出出处；标注人 A 全量复核；标注人 B 不看初标，独立标注 15 份。报告字段完全一致率与状态类字段的 Cohen's κ，分歧裁决留档。
- 用途：评估真实场景下的抽取与缺口识别能力。

**反事实任务集**
- 72 个发货任务，4 个层级各 18 个，每个任务 4–6 份报价。开发集 24 个，测试集 48 个。
- 费用结构取自真实报价和承运商官方规则。
- 在商业事实锁定的前提下，变换呈现方式：文字、表格或图片；中英混写；费用写在正文还是脚注；包税表述；资质宣称及有无证据。
- 呈现模板分为开发池与测试池，互不重叠。测试集在 M2–M4 提示词定稿前生成、冻结并记录哈希，提示词只在开发集上调试。生成器随代码公开。
- 聊天类图片渲染为中性气泡样式，不使用任何即时通讯产品的标识，标注为合成示例。

**决策规则**（标准答案的定义，事前写入协议）
1. 可行集：满足任务给定的时效约束、能送达该 FBA 仓、包税风险不为“高”。
2. 在可行集内选确定到仓成本最低者。
3. 或然费用单列为风险敞口，不计入成本。
4. 决策遗憾 = 所选方案的确定成本 − 最优方案的确定成本，报告元/票和占最优成本的比例。选中可行集外报价的情况单独计数并报告比例，不计入遗憾均值；正确答案为追问的任务不计遗憾。
5. 追问：缺失或冲突条款在其取值集合内变化时，只要可行集内的最优解会改变，正确答案就是追问，且追问清单必须覆盖该条款；否则正确答案是推荐最优解。可行集为空时，正确答案为追问。条件式回答（例如“若含税选 A，否则选 B”）按追问计分。
6. 生成器保证最优解与次优解的确定成本相差不少于 3%，避免舍入误差翻转标签；这一条在推荐类任务上成立，在决定性任务的取值网格上逐个取值成立。

**难度层级**

| 层级 | 情况 | 正确做法 |
|---|---|---|
| 显式 | 条款写明 | 直接计算 |
| 隐含 | 费用写在脚注、单列或附加费表里 | 找出隐含费用后计算 |
| 冲突 | 前后条款矛盾 | 识别冲突；按决策规则第 5 条决定推荐或追问 |
| 信息不足 | 缺少条款 | 按决策规则第 5 条决定推荐或追问 |

冲突层与信息不足层各 18 个任务，其中 12 个为决定性（正确答案为追问），6 个为非决定性（正确答案为推荐，用来测量误拒）；测试集每层 12 个中决定性 8 个、非决定性 4 个，开发集每层 6 个中 4 个和 2 个。每类可能缺失或冲突的条款在参数快照中列出有限取值集合，例如计泡系数 {5000, 6000}、住宅附加费取官方表区间的两端；多项同时缺失时取笛卡尔积。生成器在取值网格上用计算器验证最优解是否改变，验证记录随任务保存。

反事实任务的发运日期设在 2026-07-28 之后，避开新 301 关税的在途豁免（HTS 9903.05.85）。

**参数快照**
- 承运商规则、HTS 税率、MPF 与 HMF、汇率都记录来源和日期。
- 选品避开 232 商品。四类商品的合计税率（MFN + 原 301 + 新 301，USITC HTS 2026 Rev 20）：

| 商品 | HTS | MFN | 原 301 | 新 301 | 合计 |
|---|---|---|---|---|---|
| 棉制 T 恤 | 6109.10.00 | 16.5% | 清单 4A，7.5% | 12.5% | 36.5% |
| 塑料手机壳 | 3926.90.99 | 5.3% | 清单 4A，7.5% | 12.5% | 25.3% |
| 化纤双肩包 | 4202.92.31 | 17.6% | 清单 3，25% | 12.5% | 55.1% |
| 玩具 | 9503.00.00 | 免税 | 清单 4B，已暂停 | 12.5% | 12.5% |

- 10 位统计号与原 301 产品排除项在参数快照中逐项核对，含 91 FR 56538 与 91 FR 64211 两份排除项修订。
- 真实报价按报价日期选用对应的税率快照，2026-07-24 之前的报价适用当时的关税制度。
- 棉制品存在 UFLPA 扣留风险，作为或然风险项列入，不计入确定成本。

**数据标注**
- 报告中分开标注真实数据与合成数据、实测值与估算值。

## 六、方法阶梯与实验

| 编号 | 方法 | 对应的现实做法 |
|---|---|---|
| M0 | 把报价贴给通用大模型，问哪家划算、有什么风险 | 卖家现在的做法，作为“同类方案”对照 |
| M1 | 强提示词：给出检查清单、要求逐项换算 | “只改提示词够不够” |
| M2 | 大模型抽取字段，加确定性核价 | “大模型加 Excel” |
| M3 | M2 加风险与证据门控 | |
| M4 | 完整系统：原文定位、冲突识别、风险触发复核、拒答与追问 | |

模型分两档，共 6 个配置，每个配置都跑完整的 M0–M4：
- 强模型档：DeepSeek-V4-Pro（DeepSeek 官方接口）、qwen3-max（阿里云百炼）、GLM-5.3（硅基流动）、Kimi-K2.6（硅基流动）；
- 低成本档：DeepSeek-V4-Flash（DeepSeek 官方接口）、qwen-plus（阿里云百炼）。

强模型档检验“更强的模型直接使用能否做对”；低成本档检验“低成本模型加完整系统”能否达到或超过强模型直接使用的水平，并给出每次审计的成本。每个模型全程固定同一个服务商，报告中注明服务商与模型版本。图片输入用各家的视觉模型：千问 VL、Kimi-K2.6、GLM-4.5V（硅基流动）、DeepSeek-V4-Flash。图片报价在所有方法（M0–M4）中都先由本配置的视觉模型转写为文字，转写结果作为该配置各方法的共同输入；Kimi-K2.6 的视觉模型就是它自身。DeepSeek 与千问的两档共用同一个视觉模型，转写结果相同，两档差异因此只来自文字推理。转写准确率对照渲染时的原文单独报告。

**基线设置**
- M0 使用事前写好的卖家口吻提示词，与其他方法得到相同的输入，末尾加一行固定输出格式（选择或“无法确定，需要追问”，加风险列表）以便评分。M1 使用同样的输出行。
- M0、M1 的自由文本风险项按费用类型词表做规则映射，人工在隐去方法标签的条件下抽检 20%，报告映射一致率。
- M1 得到与 M4 相同的检查清单和参数快照，并在开发集上获得与 M4 相同轮数的提示词调试，两者只差架构。M0–M4 的全部提示词在测试集生成前冻结。
- 各配置在 M0–M4 中一律关闭思考模式，实际设置记入运行记录。另设“M1 开启思考模式”一组（DeepSeek-V4-Flash），只在测试集上运行，对应卖家在网页端开启深度思考的用法。
- 低成本档 M4 的跨模型复核只在 DeepSeek-V4-Flash 与 qwen-plus 之间互相进行，强模型档 M4 在强模型之间互相复核；复核调用计入该配置的成本。

**三组实验**

| 实验 | 问题 | 主要指标 |
|---|---|---|
| E1 报价理解与核价（主） | 能否算对真实到仓成本并作出正确决策 | 决策正确率（含正确追问）、字段准确率、出处准确率、核价误差、决策遗憾（每票多付的金额和比例） |
| E2 风险与证据（主） | 能否识别隐性费用、包税风险和无依据的宣称 | 风险项检出 micro-F1（合并）、隐性费用召回率、冲突与缺口检出的 F1、包税风险标记的精确率与召回率、证据状态准确率、无依据宣称的采纳率 |
| E3 复核机制（辅） | 选择性复核值不值得 | 复核比例与纠错数量的曲线、额外调用成本 |

贯穿各实验的指标：
- 拒答质量：信息不足任务的正确拒答率，以及不该拒答时的误拒率。
- 追问清单质量：覆盖了多少真实缺口。
- 每次审计的调用成本与时延。千问使用免费额度，成本按官方标价折算。

## 七、统计与事前决策规则

**统计方法**
- 分析单位是任务，采用配对设计，各模型配置作为分层。
- 主终点事前指定，三项合为一个 Holm 族，族内总体 α = 0.05。Holm 在任意相依结构下都控制总体错误率，主终点 1 与 3 共用部分数据也适用。
  1. E1：决策正确率（含正确追问），M4 对 M0，非显式三层共 36 个测试任务，6 个配置分层；双侧优效检验。
  2. E2：风险项检出 micro-F1（隐性费用、冲突与缺口、包税风险合并；包税风险“高”与“需核实”都算阳性），M4 对 M0，全部 48 个测试任务，6 个配置分层；在任务内交换方法标签做置换检验，统计量为 micro-F1 之差；双侧。
  3. 成本主张：低成本档 M4 对同厂商强模型档 M0 的决策正确率（DeepSeek-V4-Flash 对 DeepSeek-V4-Pro，qwen-plus 对 qwen3-max，2 层分层），非显式 36 个任务；非劣效检验，界值 −5 个百分点，单侧。
- 其余比较作为次要结果，只作描述性报告，给出 95% 置信区间。
- 二分类指标用 McNemar 精确检验，跨配置合并时用分层置换检验；连续指标用配对置换检验。置信区间用按任务整簇重抽的 bootstrap。
- 正式实验前冻结协议并记录哈希。
- 先用 20–40 次调用做预试验，只检查流程能否跑通。

**事前决策规则**（写进协议，结果出来后不再临时改主线）

| 情况（判定条件） | 处理 |
|---|---|
| 主终点 1 经 Holm 校正后不显著 | 主张收窄为“风险识别与追问”，决策正确率照实报告 |
| 主终点 2 经 Holm 校正后不显著 | 主张收窄为“核价与决策”，风险检出照实报告并做错误类型分析 |
| 主终点 3 未达到非劣效 | 成本主张改为“每个正确决策的调用成本”对比，照实报告 |
| M0 在显式层的决策正确率 ≥ 90% | 成效一节以非显式三层和真实报价集为主 |
| M4 对 M2 的核价绝对误差差值，95% 置信区间包含 0 | 核价改进照实写，系统增量归于风险识别与追问 |
| M4 风险标记的精确率 < 0.7 | 报告精确率与召回率的权衡，给出阈值选择依据 |
| M1 思考模式组的决策正确率点估计 ≥ M4（同为 DeepSeek-V4-Flash） | 照实报告；主张改为 M4 在成本、时延和可核对出处上的优势 |
| 真实报价集抽取字段准确率 < 0.8 | 照实报告，并分析错误类型，作为改进方向 |

**评委可能追问及对应的设计**

| 追问 | 回答 |
|---|---|
| 这不就是运费计算器吗？ | 计算器只是 M2。M3、M4 相对 M2 的增量，就是理解非结构化条款和识别风险的价值，实验里有数据 |
| 数据是你们自己编的吧？ | 真实报价集来自公开价格页并注明来源；反事实集的费用结构取自真实报价和官方规则，标准答案由两套独立计算器给出；测试集在系统定稿前冻结；评测集与生成器公开 |
| 你们能判断货代违法吗？ | 不判断。系统只标出不一致之处，并列出应当索要的单证 |
| 关税变化这么快，怎么跟得上？ | 税率是带日期的参数快照，可以替换；系统设计本身不依赖某一个税率 |
| 标准答案由你们的规则定义，M4 又内置同一规则，是不是自己出题自己答？ | M1 拿到同样的规则和参数快照，并获得同样的调试轮数；测试集模板与开发集分离并事前冻结；真实报价集独立评估 |
| 成效数字是不是都来自合成任务？ | 决策类成效来自反事实任务，报告中标明“合成任务估算”；抽取与缺口识别另有真实报价集的结果 |
| 模型更新后能复现吗？ | 记录模型名、服务商、日期、参数、提示词哈希和原始响应，冻结协议与评测集公开 |
| 卖家把报价交给第三方大模型，数据合规怎么处理？ | 报价不含个人信息；系统可接国内服务商的接口或本地部署模型；评测数据中货代名称匿名化 |
| 有没有用户？ | 对照组 M0 就是卖家现在的做法；真实报价集来自市场；如果有卖家试用反馈，放在佐证材料里 |
