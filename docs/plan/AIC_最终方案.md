# AIC「AI+跨境电商」最终方案：QuoteGuard 运价明镜（2026-10-09）

本文件取代 AIC_选题方案.md 中的方向设计。比赛规则的核对仍以 AIC_选题方案.md 第二节为准。

## 〇、一句话

QuoteGuard 帮中国跨境卖家审计美国头程物流报价，报价可以是微信文字、Excel 或价格表图片。系统做五件事：
1. 把报价折算成可比的到仓成本；
2. 找出隐性费用和前后矛盾的条款；
3. 核查“包税”报价和资质宣称有没有依据；
4. 信息不足时不给推荐，改为生成追问清单；
5. 输出一份可以核对的决策报告（“决策护照”）。

用一套可复算的评测集，把它和卖家现在的做法比较。卖家现在的做法是把报价贴给通用大模型问“哪家划算”。

## 一、选题与定位

- **作品名称**：运价明镜：跨境头程报价智能审计（15 字）。英文名 QuoteGuard。
- **使用者**：中国跨境电商卖家，以亚马逊 FBA 卖家为主，向美国发头程货（快递、空派、海派包税专线）。
- **部署形态**：独立工具，也可以作为卖家 ERP 的插件或货代比价平台的审核模块。
- **对应官方方向**：
  - 方向四：多仓协同物流与合箱优化；
  - 方向二：报关通关；
  - 方向三：账号健康与合规风控。

## 二、为什么最终定这个题（按评委视角对前几版做的自查）

QuoteGuard 前一版的设定是海外买家向中国供应商采购。这一版有五个问题，之前没有人指出：

1. **视角不对**：使用者是海外买家。中国评委理解的“AI+跨境电商”以中国卖家出海为主。
2. **需求证据弱**：只有 Accio 的用户规模可以引用，Accio 是否做报价比较也没有核实。
3. **证据实验只能用合成数据**：资质证书没有公开库，信任实验必然被质疑。
4. **细节容易被抓**：马来西亚的税费与 ST 管制规则都没有核实，有贸易背景的评委容易在细节上挑错。
5. **场景不够真实，输出没有落到行动**：真实 B2B 采购以询价和谈判为主，“让 AI 直接选供应商”这个场景不够真实；系统也没有给出可执行的输出，例如追问清单、应当索要的单证。

头程报价这个题针对上述问题逐条改进：

| 维度 | 头程报价审计 |
|---|---|
| 使用者 | 中国卖家，切题 |
| 需求证据 | 法院白皮书、海关数据、真实货代报价中的“不含项目” |
| 真实数据 | 承运商官方规则、公开的货代价格页，以及可以人工查询的资质登记库 |
| 时效性 | 2025–2026 年美国关税与小额豁免规则多次变化，报价口径随之混乱 |
| 现有工具 | 没有见到同时覆盖中文非结构化报价、包税条款歧义、资质核验和 FBA 渠道的工具 |

## 三、需求论证（已核实的证据链）

1. **纠纷集中在运费**
   - 宁波海事法院白皮书（2024-11）统计了 2021 年至 2024 年 6 月结案的跨境电商物流案件，共 400 件，标的额 1.58 亿元。
   - 争议焦点中，代理运费占 79.3%；目的港为美国的占 74.5%。
   - 这类案件占货代与多式联运案件的比例，从 9.8% 升到 52.2%。
2. **规则多次变化**
   - 2025-08-29：美国暂停所有国家的小额豁免。
   - 2026-02-20：最高法院判定 IEEPA 关税无效。
   - 之后开征第 122 条临时关税，2026-07-24 到期。
   - 2026-07-24 起，新的 301 关税对中国加征 12.5%。
   - 原有的对华 301 关税与 232 关税继续有效。
   - 2027-07-01 起，小额豁免在法律上永久废除。
   - 以上来源为白宫、律所与行业媒体。写报告时，具体税率以 Federal Register 和 HTS 原文为准。
3. **执法收紧**
   - 截至 2025-12，CBP 已对 2.46 亿多件原免税小包征税超过 10 亿美元。
   - 2026 年卖家社区报道了 5H、9H 扣货；有卖家因低申报被要求补交多票单证（报道来源为雨果网）。
4. **报价本身含隐性费用**
   - 公开的包税报价通常把以下项目列为“不含”：查验产生的仓储或滞港费、扣货损失、私人住宅派送费、高货值加价。
   - 有货代自己承认，低价包税多走低申报渠道。
   - 货代空派、海派按 ÷6000 计泡，快递按 ÷5000 或 139 in³/lb 计泡，口径不一致。
5. **卖家感知**
   - Jungle Scout 2025 年调研中，38% 的卖家把运费上涨列为主要挑战。这项调研的样本不专指中国卖家。
6. **工具空白**
   - Freightos、亚马逊 AGL、5688 运价 API 提供结构化报价或订舱，包税条款只写在自由文本里。
   - Flexport 的 MCP 只能查自家运价。
   - CostClaw 做报价归一和发票审核，面向英文海运进口商。

需求分析不发问卷、不做访谈，证据来自官方与司法统计、真实报价样本、工具对照和本项目的实测。如果有卖家试用并写反馈，可以放进佐证材料，但方案不依赖这一项。

## 四、系统设计

1. **多模态抽取与原文定位**
   - 输入：微信文字、Excel 或 CSV、价格表图片或 PDF。
   - 抽取字段：渠道、计费方式（单价阶梯、最低计费重、计泡系数）、包含与不含项目、附加费、时效、包税范围、清关方式与进口商主体（IOR）、赔付条款、有效期。
   - 每个字段都保留出处（原文片段、表格单元格或图片区域），并用脚本核对出处确实存在于原文中。
2. **冲突与缺口识别**
   - 冲突示例：报价写“双清包税”，备注却写“关税实报实销”。
   - 缺口示例：没有写计泡系数；没有写私人地址附加费；没有写有效期。
3. **确定性核价**
   - 根据货物参数（件数、尺寸、重量、货值、品名及其 HTS 税率快照）和报价条款，计算每票和每件的到仓成本。
   - 承运商附加费按官方表计算。
   - 不包税时，关税按“申报价值 × 税率快照”计算。
   - 两套独立实现交叉核对标准答案。
4. **风险与证据门控**
   - **包税合理性**：包税单价低于“按申报价值和税率测算的税费下限”时，标为合规风险，并列出应当索要的单证（进口商主体、7501 报关单、ISF）。系统只标风险，不判定货代违法。
   - **资质宣称**：例如“NVOCC”“海关高级认证”。宣称要与登记库的查询快照比对（FMC OTI 名单、海关企业信用公示平台），状态分四种：有证据、证据不足、证据与宣称矛盾、证据与本次运输不相关。
5. **风险触发复核**
   - 触发条件：存在冲突或缺口、包税不合理、证据状态不确定、多模型意见分歧。
   - 复核方式：另一家模型独立抽取，或者把候选重新排序后再判断。
   - 只在触发时追加调用，并记录额外成本。
6. **决策护照与追问清单**
   - 决策护照列出：可比成本、隐性费用、风险项、证据状态、推荐理由。
   - 信息不足时不作确定推荐，改为生成可以直接发给货代的追问清单。

## 五、数据与评测集

**真实报价集**
- 收集 30–50 份公开的货代价格页或价格表（文字和图片都有），注明来源和抓取日期。货代名称做匿名化处理。
- 由人工标注字段，其中一个子集由两人独立标注，计算一致率。
- 用途：评估真实场景下的抽取与缺口识别能力。

**反事实任务集**
- 约 40 个发货任务，每个任务 4–6 份报价。
- 费用结构取自真实报价和承运商官方规则。
- 在商业事实锁定的前提下，变换呈现方式：
  - 文字、表格或图片；
  - 中英混写；
  - 费用写在正文还是脚注；
  - 包税表述；
  - 资质宣称及有无证据。

**难度层级**

| 层级 | 情况 | 正确做法 |
|---|---|---|
| 显式 | 条款写明 | 直接计算 |
| 隐含 | 费用写在脚注、单列或附加费表里 | 找出隐含费用后计算 |
| 冲突 | 前后条款矛盾 | 识别冲突 |
| 信息不足 | 缺少关键条款 | 正确答案是拒答并追问 |

**参数快照**
- 承运商规则、HTS 税率和汇率都记录来源和日期。
- 选品时避开 232 商品，降低关税叠加的不确定性。

**数据标注**
- 报告中写明哪些是真实数据、哪些是合成数据。

## 六、方法阶梯与实验

| 编号 | 方法 | 对应的现实做法 |
|---|---|---|
| M0 | 把报价贴给通用大模型，问哪家划算、有什么风险 | 卖家现在的做法，作为“同类方案”对照 |
| M1 | 强提示词：给出检查清单、要求逐项换算 | “只改提示词够不够” |
| M2 | 大模型抽取字段，加确定性核价 | “大模型加 Excel” |
| M3 | M2 加风险与证据门控 | |
| M4 | 完整系统：原文定位、冲突识别、风险触发复核、拒答与追问 | |

模型分两档，共 6 个配置，每个配置都跑完整的 M0–M4：
- 强模型档：DeepSeek-V4-Pro（DeepSeek 官方接口）、qwen3-max（阿里云百炼）、GLM-5.3（硅基流动）、Kimi-K2.6（硅基流动）；
- 低成本档：DeepSeek-V4-Flash（DeepSeek 官方接口）、qwen-plus（阿里云百炼）。

强模型档检验“更强的模型直接使用能否做对”；低成本档检验“低成本模型加完整系统”能否达到或超过强模型直接使用的水平，并给出每次审计的成本。每个模型全程固定同一个服务商，报告中注明服务商与模型版本。图片输入用各家的视觉模型：千问 VL、Kimi-K2.6、GLM-4.5V（硅基流动）、DeepSeek-V4-Flash。

**三组实验**

| 实验 | 问题 | 主要指标 |
|---|---|---|
| E1 报价理解与核价（主） | 能否算对真实到仓成本 | 字段准确率、出处准确率、核价误差、选择正确率、决策遗憾（每票多付的金额和比例） |
| E2 风险与证据（主） | 能否识别隐性费用、包税风险和无依据的宣称 | 隐性费用召回率、冲突与缺口检出的 F1、包税风险标记的精确率与召回率、证据状态准确率、无依据宣称的采纳率 |
| E3 复核机制（辅） | 选择性复核值不值得 | 复核比例与纠错数量的曲线、额外调用成本；多模型在共享与独立顺序下的同选率（沿用工行杯方法，用来论证复核设计） |

贯穿各实验的指标：
- 拒答质量：信息不足任务的正确拒答率，以及不该拒答时的误拒率。
- 追问清单质量：覆盖了多少真实缺口。

## 七、统计与事前决策规则

**统计方法**
- 分析单位是任务，采用配对设计。
- 检验用 McNemar 精确检验和配对置换检验，按任务做 bootstrap 置信区间，多重比较用 Holm 校正。
- 正式实验前冻结协议并记录哈希。
- 先用 20–40 次调用做预试验，只检查流程能否跑通。

**事前决策规则**（写进协议，结果出来后不再临时改主线）

| 情况 | 处理 |
|---|---|
| M0 在显式层级几乎全对 | 主结果报告隐含、冲突、信息不足三层，以及真实报价集上的表现 |
| M4 相比 M2 在核价上没有显著改进 | 主张收窄为“风险识别与拒答”，核价改进照实写 |
| M4 的风险标记误报率高 | 报告精确率与召回率的权衡，给出阈值选择依据 |
| 真实报价集抽取准确率低 | 照实报告，并分析错误类型，作为改进方向 |

## 八、评分对照与评委追问

| 评分项 | 拿高档的依据 |
|---|---|
| 创新 25 | 现有工具中没有见到覆盖中文多模态报价审计、包税合理性核查、资质证据门控、拒答与追问的系统；还提供可复算的评测集 |
| AI 技术 20 | 多模态抽取加出处核对、大模型与规则混合、风险触发的跨模型复核、可校准的拒答；方法阶梯消融说明每一层的作用 |
| 需求 15 | 司法统计、海关数据、政策时间线、真实报价中的不含项目、工具空白，五类证据 |
| 实施 15 | 完整可运行的流程、演示、原始记录、冻结协议、测试 |
| 成效 15 | 对比卖家现在的做法（M0）：每百票的多付金额、漏掉的风险数、拒答与追问的质量、单票成本 |
| 总结 10 | 部署路径（ERP 插件、平台审核）、规则更新机制、扩展到欧盟与其他渠道 |

**评委可能追问及对应的设计**

| 追问 | 回答 |
|---|---|
| 这不就是运费计算器吗？ | 计算器只是 M2。M3、M4 相对 M2 的增量，就是理解非结构化条款和识别风险的价值，实验里有数据 |
| 数据是你们自己编的吧？ | 真实报价集来自公开价格页并注明来源；反事实集的费用结构取自真实报价和官方规则，标准答案由两套计算器给出；评测集公开 |
| 你们能判断货代违法吗？ | 不判断。系统只标出不一致之处，并列出应当索要的单证 |
| 关税变化这么快，怎么跟得上？ | 税率是带日期的参数快照，可以替换；系统设计本身不依赖某一个税率 |
| 和工行杯有什么关系？ | 只复用了冻结执行、统计检验等底层工具。问题、数据、系统和结论都是新的 |
| 有没有用户？ | 对照组 M0 就是卖家现在的做法；真实报价集来自市场；如果有卖家试用反馈，放在佐证材料里 |

## 九、交付物

- **技术方案 PDF**：按附件 2 大纲组织：作品概述、需求分析、AI 技术选择与运用、项目实施、应用成效、总结展望、附录。
- **演示视频，3–5 分钟**：上传三份报价（图片、微信文字、Excel），依次展示抽取与出处、隐性费用、包税风险、资质状态、决策护照；再展示一个信息不足、系统拒答并生成追问清单的例子。
- **佐证材料**：评测集说明、协议哈希、测试报告、与通用大模型的对照记录；如果有卖家反馈，一并放入。
- **代码与数据**：放百度网盘。货代名称匿名化，材料中不出现学校信息。

## 十、剩余风险与预案

| 风险 | 预案 |
|---|---|
| 关税叠加规则核实不清 | 选品避开 232 商品，按 Federal Register 原文定税率；无法确定的，写为固定假设 |
| 登记库无法批量访问 | 由人工查询并保存快照，系统读取快照 |
| 视觉接口差异（千问新地址、Kimi 只收 base64） | 预试验第一步先验证 |
| 标注工作量大 | 云端会话初标，人工抽检复核，报告一致率 |
