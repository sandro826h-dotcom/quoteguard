# 运价明镜演示系统

本目录是 QuoteGuard 的本地网页演示，用于 3–5 分钟演示视频。页面按审计流程分六步：报价输入、字段抽取与原文出处、冲突与缺口、包税风险与资质证据、到仓成本对比、决策护照与追问清单。

演示回放预试验已记录的模型输出，运行时不调用模型、不联网。三个案例都是 dev 集合成任务，页面底部固定标注数据性质与所用配置。

## 运行

在仓库根目录执行：

```bash
python3 -m http.server 8000 -d demo     # 浏览器打开 http://localhost:8000
```

`demo/data/` 已随仓库提交，直接打开即可。需要从记录重新生成数据时：

```bash
pip install -r requirements.txt          # 首次运行
PYTHONPATH=src python3 demo/build_data.py
```

`build_data.py` 只读 runs/ 下的预试验观测，用仓库代码离线重算 M0 与 M4 的输出和各步骤数据，写入 `demo/data/cases.json` 与 `demo/data/assets/`。脚本结束前逐项核对决策、选择、追问清单和各报价成本，与 `runs/derived/pilot_rescore_20261010_fullreview` 不一致时报错退出。

重新截图（需要 Node 与预装的 Playwright、Chromium）：

```bash
python3 -m http.server 8765 -d demo &
node demo/screenshots.js
```

## 案例

| 案例 | 任务 | 层级 | 报价形态 | 可切换配置 | 系统结论 | 标准答案 |
|---|---|---|---|---|---|---|
| A | T-dev-004 | 冲突 | 图片 1、文字 2、Excel 1，空派 | deepseek-flash、qwen-plus | 追问报价4整票最低计费重 | 同左 |
| B | T-dev-010 | 隐含 | Excel 4，快递 | deepseek-flash、qwen-plus | 推荐报价2 | 同左 |
| C | T-dev-020 | 信息不足 | 图片 1、Excel 1、文字 2，空派 | GLM-5.3、Kimi-K2.6 | 追问报价2包税条款，另追问报价3、4报关费 | 追问报价2包税条款 |

案例 C 的两项额外追问来自跨模型复核：报价3、4原文都写明报关费 400 元/票，两个模型各漏抽其中一份，复核时形成“一方漏抽”的冲突，系统按决定性冲突列入追问。正式评分中这两个配置的决策记为正确，追问字段比标准答案多两项。第 6 步“对照：标准答案”折叠区按正式评分口径列出，并逐报价说明成本差异原因。

## 页面操作

- 顶栏切换案例与配置；“上传报价”计算文件 SHA-256，与内置原件匹配时跳到对应案例并高亮该报价，其他文件只显示提示。内置原件在 `demo/data/assets/`。
- 地址可直达，例如 `#case=A&cfg=ds_flash&step=3`；第 2 步加 `&q=C1` 选定报价。
- 第 2 步点击字段行，右侧原文高亮出处片段；图片报价并排显示原图与视觉模型转写。
- 第 6 步“复制”复制追问清单，“打印护照”输出一页 A4。

## 数据口径

- 字段、冲突、包税判定、成本行项均由预试验记录经仓库代码重算，推荐理由与风险项由数据按模板拼成句子。
- 冲突字段未追问时，成本取较低取值；冲突字段和缺失的必需字段都在第 5 步显示其他取值下的区间。页面中的“计算成本”即此口径。
- “运费之外另计的费用项”指燃油、报关、附加费等在运费之外计入成本的项目，范围比评测集中“隐含费用”的定义宽。
- 资质登记库为合成快照（syn-registry-2026-10-10-dev）。
- 第 6 步“运行信息”中的记账成本取 M4 输出的成本，含图片转写份额与复核方抽取。
- 预试验的抽取错误原样保留，例如案例 A 中 qwen-plus 把赔付条款误读为资质宣称。

## 文件

- `index.html`、`app.js`、`style.css`：静态页面，原生 JavaScript，无外部依赖。
- `build_data.py`：数据构建脚本。
- `data/`：案例数据与报价原件副本。
- `screenshots/`、`screenshots.js`：界面截图与截图脚本。
- `演示脚本.md`：视频分镜与旁白。
